# Platform, delivery and operator-experience evidence audit

Audit started **2026-09-19**, completed **2026-09-20** (Europe/Belgrade). Baseline: **`3597b6b`**. This is an evidence note supporting the [living roadmap](../ROADMAP.md), not a second prioritization source. No product code, deployment, private traces, or secrets were changed or examined. Public-cloud readiness and the value of a hosted offering remain separate decisions; [ADR-002](../decisions/ADR-002-deployment-model.md), [ADR-005](../decisions/ADR-005-architecture-for-scale.md), [ADR-008](../decisions/ADR-008-security-auth-privacy.md), and the superseded [pricing ADR](../decisions/ADR-003-pricing-strategy.md) contain conflicting assumptions that need an explicit decision before cloud investment.

## Meaning of the labels

- **DONE**: the specifically named capability exists in code with supporting tests or direct inspection. This does not imply production certification or that every related feature is finished.
- **PARTIAL**: useful implementation exists, but stated scope exceeds the observed implementation.
- **NOT STARTED**: no implementation for the specifically named capability was found in the inspected runtime, test, and delivery surfaces; related primitives may exist.
- **UNVERIFIED**: there is a claim or plausible path, but this audit has not established its runtime behavior.

Existing uncommitted work was present before this audit: CI ordering, frontend API contracts/URL handling, frontend formatting/types, contract-check scripts/tests, README and DISCOVERIES updates. It was preserved. References to those paths describe their stable baseline behavior unless explicitly called **working-tree-only**. Those edits are not counted as shipped work. GitHub/PR state is tracked by the main roadmap audit, separately from this code inspection.

## Tenant and execution boundaries

**DONE: scoped core reads and key primitives.** [`get_repository`](../../api/dependencies.py) constructs a tenant-scoped facade; [`SessionRepository`](../../storage/repositories/session_repo.py), [`EventRepository`](../../storage/repositories/event_repo.py), and [`CheckpointRepository`](../../storage/repositories/checkpoint_repo.py) filter reads by tenant directly or through the parent session. [`auth/service.py`](../../auth/service.py) implements scoped key create/list/revoke operations. [`tests/test_tenant_isolation.py`](../../tests/test_tenant_isolation.py) proves tenant separation for session listing. It contains two tests, not a complete route/operation isolation matrix.

**PARTIAL: application mode and authentication policy.** [`api/dependencies.py`](../../api/dependencies.py) rejects non-loopback client addresses in local mode. In the cloud branch, [`get_tenant_from_api_key`](../../auth/middleware.py) returns `local` when the authorization header is absent. This is a specific policy gap for a hosted deployment; it is not evidence that every endpoint leaks every tenant. [`api/main.py`](../../api/main.py) calls `get_config()`, while [`config.py`](../../agent_debugger_sdk/config.py) returns default `Config()` when uninitialized; environment-based SDK configuration is read by `init()`. Server mode must be made explicit and verified at startup before hosted auth claims can be accepted.

**PARTIAL: routes do not consistently use the shared tenant boundary.** [`api/cross_session_routes.py`](../../api/cross_session_routes.py) defines its own `get_repository()` at lines 23–29, hard-codes `tenant_id="local"`, and enters a session without a paired dependency cleanup. [`GET /api/analytics`](../../api/analytics_routes.py) has no auth dependency; [`analytics_db.py`](../../api/analytics_db.py) explicitly documents its database as local-only and not tenant-isolated. These need either a local-only route boundary or a tenant-aware implementation before being included in a hosted surface.

**PARTIAL: checkpoint ownership on write.** [`collector/server.py`](../../collector/server.py) verifies the session's ownership before adding HTTP events, but `ingest_checkpoint()` directly calls `create_checkpoint()` with supplied `session_id` and `event_id`. [`CheckpointRepository.create_checkpoint`](../../storage/repositories/checkpoint_repo.py) writes these references without verifying ownership or that the event belongs to that session; reads subsequently join the parent session's tenant. This is a scoped write-integrity gap. A future gate must test attempts to attach a checkpoint to another tenant's session/event, plus mismatched references within one tenant, and require rejection with no mutation.

**PARTIAL: custom breakpoint expressions are an execution boundary.** [`set_breakpoint`](../../api/stepper_routes.py) accepts a `BreakpointType` and unrestricted `condition_value` after requiring access to the session. The `/step` route loads the accessible session and calls `AgentStepper.step()`. `CONTINUE` calls [`Breakpoint.should_trigger`](../../agent_debugger_sdk/core/stepper.py), whose custom-condition branch evaluates that string with `eval(..., {}, {"event": event})`. An empty globals dictionary does not remove Python builtins. Static reachability therefore supports a server-process expression-evaluation concern for callers allowed to access a session. No exploit was run and no cross-tenant reachability is asserted. Disable custom expressions on remote surfaces or replace them with a constrained predicate grammar before widening access. Test forbidden syntax and bounded evaluation, rather than testing only normal conditions.

**UNVERIFIED: authenticated-tenant claims in the real-process E2E suite.** [`tests/e2e/conftest.py`](../../tests/e2e/conftest.py) inserts an API key and sends its header, but starts a separate `uvicorn api.main:app` process without explicitly initializing server cloud mode. Its `cfg_mod.init(...)` runs in the SDK test process. Combined with `get_config()` above, this setup supports real transport/storage testing but does not prove that the server authenticated the inserted key or stored rows under its tenant. Add explicit server-mode setup, persisted-tenant assertions, absent/invalid-key rejection and two-tenant negative cases before calling the suite an authentication proof.

[`tests/test_redaction_integration.py`](../../tests/test_redaction_integration.py), despite its name, calls only `pipeline.apply()` and does not inspect actual persistence.

## Scale and delivery

**PARTIAL: streaming primitives.** The memory buffer has event/session limits and bounded subscriber queues; overflow removes a slow subscriber in [`collector/buffer.py`](../../collector/buffer.py). SSE has keepalives and a maximum connection duration in [`api/services/ingestion.py`](../../api/services/ingestion.py), and the frontend reconnects in [`App.tsx`](../../frontend/src/App.tsx). No event cursor or `Last-Event-ID` recovery is emitted by this generator. Browser reconnection alone does not prove gap-free replay after disconnect or overflow.

**PARTIAL: Redis backend, not a verified scale deployment.** [`buffer_redis.py`](../../collector/buffer_redis.py) implements `XADD` plus pub/sub. Its default constructor references `Redis.from_url` even though `Redis` is imported only under `TYPE_CHECKING`; a no-network constructor probe raised `NameError: name 'Redis' is not defined`. [`api/main.py`](../../api/main.py) selects Redis when `REDIS_URL` is present but does not pass that URL to `create_buffer`. Redis subscriber queues are unbounded, `get_events()` and `flush()` return empty lists, and tests predominantly inject mock clients ([example](../../tests/test_buffer_redis.py)). Consumer-group recovery, persistence workers and a tested multi-process fan-out path are not delivered by this implementation.

**PARTIAL: database portability.** [`storage/engine.py`](../../storage/engine.py) accepts configurable async URLs and includes Alembic migration support. Application lifespan prepares schema only when the URL contains `sqlite`. PostgreSQL dependencies are optional in [`pyproject-server.toml`](../../pyproject-server.toml). A real PostgreSQL migration/upgrade/restore matrix was not run and is **UNVERIFIED**; SQLite success must not stand in for it.

**PARTIAL: clustering at scale.** [`cross_session_routes.py`](../../api/cross_session_routes.py) reads up to 500 sessions and 1,000 events per session, computes rankings inline, and uses a simplified replay value. [`services/sessions.py`](../../api/services/sessions.py) caps list enrichment at 100 sessions. These bounds keep work finite, but results need explicit coverage/truncation indicators and measured latency before they can support large-fleet completeness claims.

**PARTIAL: server packaging.** [`pyproject-server.toml`](../../pyproject-server.toml) declares server modules and force-includes the frontend bundle; [`publish.yml`](../../.github/workflows/publish.yml) swaps it into `pyproject.toml`, builds the frontend, builds distributions and publishes. No clean-install server-wheel startup/migration/browser check appears between build and publish. The wheel package/force-include configuration does not explicitly include root `alembic.ini`, while [`storage/engine.py`](../../storage/engine.py) resolves that file and [`migrations/env.py`](../../storage/migrations/env.py) passes it to `fileConfig`. A clean wheel startup is **UNVERIFIED** and should be an acceptance gate. No fresh wheel was built in this audit.

**PARTIAL: container artifact.** [`Dockerfile`](../../Dockerfile) has a frontend stage and non-root runtime, but copies `pyproject-server.toml` under that name and then runs `pip install -e .` without creating `pyproject.toml`. Unlike the publishing workflow, it has no swap step. This is a concrete build-definition gap; Docker was not run. [`docker-compose.yml`](../../docker-compose.yml) mounts `/app/traces`, while the default SQL database URL points to `./data/agent_debugger.db` in [`storage/engine.py`](../../storage/engine.py). Verify the actual writable data volume and restart persistence rather than treating the presence of Compose as deployment completion.

**PARTIAL: install-to-first-value DX.** The SDK wheel only packages `agent_debugger_sdk`, while its [`CLI`](../../agent_debugger_sdk/cli.py) expects repository `scripts/seed_demo_sessions.py`, `api.main`, and a frontend source tree for demo/serve commands. The server distribution uses the same `peaky-peek` console-script name with a different argument interface ([server CLI](../../api/cli.py)). An installed SDK-only path, installed SDK+server path and source-checkout path need separate clean-environment acceptance tests. Existing [`test_package.py`](../../tests/test_package.py) checks imports/metadata and skips its circular-import test; it is not an installed artifact test.

## Quality gates and test isolation

**DONE: several mandatory checks are configured.** Baseline [`ci.yml`](../../.github/workflows/ci.yml) has Python 3.10/3.11/3.12 tests, lint, a 70% coverage threshold, frontend TypeScript/build, Vitest and an API-contract check. **PARTIAL:** Pyright is advisory, Bandit suppresses failure, and dependency-review is advisory; separate pip-audit/npm-audit steps do gate. The coverage upload points at `coverage.xml`, but the test command requests only `term-missing`; verify or add XML generation before relying on uploaded results. Configured gates are not evidence of current green runs.

The **working-tree-only** CI edits move frontend dependency installation before Python contract tests and consolidate npm installation. New route/type contract scripts and regressions are also present locally. They deserve review and execution in their own change; this note does not mark them released.

**PARTIAL: isolation.** [`tests/conftest.py`](../../tests/conftest.py) creates a fresh temporary directory at import, installs a worker database URL, resets some globals, and offers function-scoped isolated databases. It reads `PYTEST_XDIST_WORKER_ID`, while the intended xdist worker variable is `PYTEST_XDIST_WORKER`. Crucially, a fresh `mkdtemp()` is already created per process, so the wrong variable alone does not prove that workers share the same file. The shared app/global configuration, process environment and ContextVar hooks need separate diagnosis. [`tests/e2e/conftest.py`](../../tests/e2e/conftest.py) explicitly clears pipeline ContextVars around scenarios because earlier unit tests can leak persister hooks. A worker-variable patch alone cannot establish that the complete flaky coverage job is repaired.

**NOT STARTED: an enforced real-browser workflow gate.** Vitest/jsdom component tests and real-process API scenarios are useful but distinct. [`scripts/record_demo_gifs.js`](../../scripts/record_demo_gifs.js) uses Playwright to record demonstrations; it does not establish browser CI acceptance. The minimal gate should exercise seeded session discovery → verdict/evidence → replay/checkpoint → search navigation, fail on console/network errors, and include empty/error/reconnect states. Keyboard navigation and basic automated accessibility checks should run on the same journeys; their coverage is **UNVERIFIED** today.

## Validation performed

The audit used source/manifest inspection and these bounded validations; no full test suite, browser, external service, Docker build, cloud deployment or destructive operation was run.

```bash
  tests/test_redaction.py tests/test_redaction_security.py \
  tests/test_tenant_isolation.py tests/test_auth_middleware_unit.py \
  tests/collector/test_collector_persistence.py --maxfail=3

.venv-ci/bin/pyright --pythonpath .venv-ci/bin/python --outputjson
# Pyright 1.1.405; 213 files; 174 errors; 0 warnings; exit 1.
# 45 errors are reportMissingImports: installed optional dependencies matter.
```

The interpreter-unspecified Pyright run reported 222 errors, including 91 missing imports. This difference is why neither count is presented as a universal replacement for historical CI baselines.

A synthetic no-network Python probe constructed `RedisEventBuffer()` and received `NameError: name 'Redis' is not defined`. A separate synthetic `TraceEvent` probe applied prompt+PII redaction and verified: content became `[REDACTED]`, the original input remained unchanged, and a metadata email remained unchanged. These probes establish only those local code paths; they do not claim end-to-end deployment validation.
