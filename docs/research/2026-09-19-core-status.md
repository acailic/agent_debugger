# Core SDK, replay, and interoperability: implementation audit

Audit date: 2026-09-19. Baseline: `main`, commit `3597b6b`.

This is an evidence note for the [living roadmap](../ROADMAP.md), not a competing prioritization document. It reviews the current working tree, including the existence of pre-existing local changes; those changes were not edited. The review reads source and tests and runs a bounded local test selection. It does not establish production readiness, publication on PyPI, live framework compatibility, or benchmark performance.

Status meanings:

- **DONE**: the precisely stated capability is implemented; execution evidence is identified separately.
- **PARTIAL**: useful implementation exists, but an essential part of the stated workflow is missing.
- **NOT STARTED**: no implementation was found in the named source scope; this does not mean no related research exists.
- **UNVERIFIED**: the claim needs evidence unavailable or not collected in this audit.

## Adapter maturity: existence is not compatibility

[ADR-004](../decisions/ADR-004-target-users-framework-priority.md) is historically stale where it labels CrewAI and AutoGen “not started.” [The current registry](../../agent_debugger_sdk/auto_patch/__init__.py) registers seven adapters. Their depth and evidence differ:

| Integration | Status | Implemented depth / remaining evidence |
|---|---|---|
| LangChain callback adapter | **PARTIAL** | [Handler](../../agent_debugger_sdk/adapters/langchain/handler.py) and [adapter](../../agent_debugger_sdk/adapters/langchain/adapter.py) capture LLM/tool/chain callbacks; [dedicated tests](../../agent_debugger_sdk/adapters/tests/test_langchain/) exist. Real supported-version matrix and LangGraph graph-state continuation are not established by this audit. |
| PydanticAI | **PARTIAL** | [Adapter.instrument](../../agent_debugger_sdk/adapters/pydantic_ai/adapter.py) wraps `agent.run`, captures returned messages and provides explicit recording methods. `trace_session` alone opens a context; it does not install that run wrapper. [Instrumentor](../../agent_debugger_sdk/adapters/pydantic_ai/instrumentor.py) exposes callbacks rather than an installed OTel span processor. Live-version compatibility remains unverified. |
| OpenAI / Anthropic provider auto-patch | **PARTIAL** | [OpenAI adapter](../../agent_debugger_sdk/auto_patch/adapters/openai_adapter.py) and [Anthropic adapter](../../agent_debugger_sdk/auto_patch/adapters/anthropic_adapter.py) target non-streaming calls; both explicitly pass streaming through without capture. ## Claims that should change in planning

1. Keep M2.3 **DONE for semantic API restore**, but separately mark SDK/API restore convergence and execution continuation **PARTIAL / NOT STARTED**. The prefix copy is real; describing every entry point as equivalent would conceal missing auth/provenance behavior.
2. Keep recorded replay/stepper features **DONE in their data-navigation scope**. ADR-007's re-execution mode and a live debugger require additional work. Neither a restored Session nor a stored BranchPoint establishes that an agent ran again.
3. Replace framework-wide “complete” claims with an adapter capability/version table. CrewAI/AutoGen are **PARTIAL**, not absent; PydanticAI/LangChain still require compatibility evidence and authenticated delivery validation.
4. Describe OTLP support as **exporter setup only** until an event-to-span bridge and a receiving contract exist. Do not plan an OTLP receiver as if it were merely a configuration toggle.
5. Retain the [roadmap's](../ROADMAP.md) HTTP end-to-end suite as evidence that a tested authenticated transport path exists. Do not extend that evidence to no-key setup or every auto-patch integration.

## Gaps with immediate product consequences

- **Onboarding can record only in memory.** A separate-process quickstart without a key does not activate HttpTransport. A user can successfully run an agent and still see no persisted session in the UI. Verify the documented clean-install journey before measuring onboarding conversion.
- **Restore has two different contracts.** API restore preserves the historical prefix; SDK restore does not consume that route and fetches protected resources without SDK auth headers. Establish one restore protocol and prove an authenticated restore -> continuation -> audit path.
- **Auto-patch delivery has weaker guarantees than manual tracing.** The separate transport ignores non-success HTTP responses and uses a process-global session. Add explicit delivery status, bounded buffering, session lifecycle and tenant/auth propagation before calling these integrations production ready.
- **The custom breakpoint evaluator is an execution boundary.** [Breakpoint.should_trigger](../../agent_debugger_sdk/core/stepper.py) calls `eval(condition, {}, {"event": event})`; [set_breakpoint](../../api/stepper_routes.py) accepts `CUSTOM_CONDITION`. Empty globals do not remove Python builtins. Replace expression execution with an allowlisted condition representation before exposing this facility to untrusted clients. This finding is source-based; no exploit was executed.
- **Package tests run inside the source tree.** [test_package.py](../../tests/test_package.py) checks imports and metadata but does not demonstrate `serve`/`seed`/`demo` from an isolated installed wheel. A distribution acceptance test must run outside the checkout.

## Validation performed

The following bounded run used the existing Python 3.12 `.venv-ci` environment, temporary SQLite fixtures, no xdist and no coverage gate:

```bash
.venv-ci/bin/python -m pytest -q \
  tests/test_restore_semantics.py tests/test_checkpoint_restore.py \
  tests/test_replay_depth_l3.py tests/test_stepper.py tests/test_telemetry.py \
  tests/test_sdk_transport.py tests/auto_patch/test_openai_adapter.py \
  tests/auto_patch/test_crewai_adapter.py tests/auto_patch/test_autogen_adapter.py \
  --disable-warnings
```

Result: **225 passed, 2 failed in 3.10 seconds**. Both failures are in `TestCheckpointEndpoints` in [test_checkpoint_restore.py](../../tests/test_checkpoint_restore.py), importing `iter_app_api_routes` with `from conftest import ...`: `ModuleNotFoundError: No module named 'conftest'`. The helper exists in [tests/conftest.py](../../tests/conftest.py); this invocation did not make it importable under that top-level name. No source changes or test-path workaround were applied. This is not a green-suite claim.

A corrected, no-network Python probe using a mocked HttpTransport and a no-key `Config(endpoint="http://127.0.0.1:18999")` confirmed two local events existed and `HttpTransport` was not constructed. The initial probe mistakenly treated async `get_events()` as synchronous and failed; the corrected probe awaited it and completed successfully. The same probe confirmed `sample_rate` is absent from `Config.__dataclass_fields__` and the six framework/provider packages above are absent from `.venv-ci`.

The existing [HTTP scenario tests](../../tests/e2e/) were inspected, not executed. No service was started, no full suite or production database was used, and no public package/framework-release claim was verified online. Absence findings are bounded to the source directories and symbols explicitly named above.
