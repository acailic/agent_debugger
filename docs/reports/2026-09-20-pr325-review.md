## Specification

No missing requirement from issue #311 was found. The minimal concrete subclass
covers synchronous no-getter, value, disabled, `None` and async-getter fallback;
the async entry point covers no-getter, synchronous getter, awaited coroutine
getter and disabled policy. The three additional cases are relevant scope.

Optional robustness improvements from Q03 remain: zero threshold, empty policy,
async missing-field handling and async argument forwarding. A separate local
behavior probe exercised 18 policy/entry-point combinations successfully, but
those assertions are not yet committed regression tests.

The sync method's async-getter fallback has a **pre-existing coroutine lifecycle
defect**: it returns the default without awaiting or closing the coroutine. A
direct production call reproduced `RuntimeWarning: coroutine ... was never
awaited`; the async getter body did not execute. PR #325 closes the coroutine
inside its test, so its warning-free result only proves the requested default
return behavior. It does not prove warning-free production behavior. This defect
exists at the merge-base and is not introduced by the PR.
